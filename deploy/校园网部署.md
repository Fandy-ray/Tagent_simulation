## 七、与标准 Docker 部署的差异（重要）

这台机器**没有 sudo**，装不了 docker daemon，`apt` 也用不了。为了把 OpenNotebook 原样跑起来：

1. **容器运行时**：用 udocker（PRoot 用户态）直接跑官方镜像 `lfnovo/open_notebook:v1-latest`，
   镜像经 `crane` 从 daocloud 镜像站导出后导入，数据卷映射 `opennotebook/notebook_data → /app/data`。
   所以**没有 `docker` / `docker compose` 命令**，`docker-compose.yml` 在这台机器上不适用。
2. **数据库**：镜像本身不带 SurrealDB，改为原生运行 SurrealDB 2.7.0（与 compose 里 `surrealdb:v2` 同大版本），
   监听 127.0.0.1:8000，数据沿用本机搬来的 `surreal_data/mydatabase.db`。
3. **镜像补丁**：v1-latest 镜像里 Next.js 的 `dist/server/dev/` 目录被裁掉了，`next start` 会报
   `Cannot find module '../dev/browser-logs/file-logger'`。已用同版本 `next@16.3.8` 的 npm 包补齐整个
   `node_modules/next/dist/`（原目录备份在 `.udocker/containers/on/ROOT/app/frontend/node_modules/next/dist.bak`）。
   换镜像/重建容器后需要重新补。
4. 笔记本口令（`OPEN_NOTEBOOK_PASSWORD`）保护 5055/8502，TAgent 后端与前端代理自动携带；直接开 8502 时要手动输一次。
5. 参考文献已启用并入库：`run-server.sh` 里 `TAGENT_REFERENCES=1`，仓库自带的 14 篇
   《系统仿真学报》论文（`references/*.md`）与教材一起建进了检索索引，
   `/knowledge` 里可以看到 `references: 14`。首次带论文重建索引约 5–8 分钟，之后走缓存。

## 八、排障

- **主站打不开**：`ss -tln | grep 5173`；没有就 `bash ~/tagent/run-server.sh`，看 `logs/deploy-*.log`。
- **答疑报「没有可用模型」**：看 `5173/models` 或 `curl http://127.0.0.1:5001/v1/models`；
  空就说明 `model_providers.json` 丢了或被改坏。
- **笔记本连不上**：`curl -s http://127.0.0.1:5001/knowledge` 看 `notebook_reachable`；
  再看 `logs/opennotebook.log`、`logs/surreal.log`，以及 `pgrep -af 'udocker run|surreal start'`。
- **嵌入模型下载失败**：`run-server.sh` 已设 `HF_ENDPOINT=https://hf-mirror.com`；
  仍失败就把本机 `~/.cache/huggingface` 里 `shibing624/text2vec-base-chinese` 拷到服务器同名目录。
