# 架构分析与拆分方案（新版 OpenNotebook）

> 这份文档回答四件事：tagent 现在的 agent 架构是什么样、OpenNotebook 是什么样、
> OpenNotebook 哪些用得上哪些用不上、拆出来的新版怎么组织。
> 后端已并进 `TAgent重写版/basic-agent`（2026-11-11）。前端仍在 `opennotebook新版/frontend/`，由启动脚本拉到 8502。

---

## 一、tagent 现在的 agent 架构

### 1.1 两个进程

| 部分 | 位置 | 技术 | 端口 |
|---|---|---|---|
| 后端 basic-agent | `TAgent重写版/basic-agent/` | Flask + waitress，Python 3.12（uv） | 5001 |
| 前端 tagentnote | `tagentnote/` | SvelteKit + Svelte 5 + Tailwind 4 | 5173（开发）/ 4173（预览） |

前端经 Vite 代理把 `/agent-api` 转到 5001、`/opennotebook-api` 转到 5055（只放白名单里的几个请求，见 `tagentnote/notebook-proxy.ts`）；`/notebook` 页面用 iframe 嵌 OpenNotebook 自己的界面（8502）。

### 1.2 后端分层（`tools/check_architecture.py` 强制）

```
main.py → app/factory.py:create_app → app/container.py（装配）→ app/api/__init__.py（注册蓝图）

app/api/         HTTP 层：解析参数、鉴权、把结果转成 JSON / SSE；唯一能碰 Flask 的地方（加 factory.py）
app/service/     业务层：收普通参数、回普通对象；流式就回生成器，由 api 层包 stream_with_context
app/agent/       LangGraph 图：answer / exam / flash / grade / essay / annotate / edit，每种能力一张图
app/rag/         知识库：本地（FAISS + text2vec）、笔记本（调 OpenNotebook）、组合
app/repository/  SQLite 仓储（learning_store.py：每线程一个连接、WAL、MIGRATIONS + user_version）
app/infra/       对外调用：模型客户端、原样转发客户端
app/schema/      pydantic 数据模型
app/prompts/     提示词
app/util/        纯工具函数
app/config.py    唯一允许读环境变量的地方
```

检查脚本的 6 条规则：没有未定义的名字、没有没用的 import、依赖方向不能反（比如 repository 不能 import service，api 不能直接 import repository）、`os.getenv` 只许出现在 `config.py`、Flask 只许出现在 `api/` 和 `factory.py`、controller 之间不互相 import。

### 1.3 agent 是怎么跑的

- `app/agent/runtime.py` 的 `AgentDeps(knowledge_base, client_factory, provider, deadline, tuning)` 作为 LangGraph 的 `context_schema` 注入每个节点。
- 节点签名统一 `(state, runtime: Runtime[AgentDeps])`；扇出用 `Send`，合并用 `Annotated[list, operator.add]`，并发上限 16。
- 公共节点在 `app/agent/nodes.py`：`json_call`（要模型回 JSON）、`json_call_streaming`、`sample_quiz_material`、`search_text`。
- service 层（`chat_service`、`quiz_service`……）负责准备输入、调图、把图的输出转成接口要的形状。

### 1.4 知识库统一接口

local / notebook / composite 三种实现都提供：`describe()`、`admin_snapshot()`、`warm_up()`、`ensure_index()`、`quiz_documents()`、`retrieve(query, notebook_ids)`、`search(query, *, k, notebook_ids)`、`chunks(notebook_ids)`、`sample_exam_pieces(topic, notebook_ids)`、`close()`。笔记本实现（`app/rag/opennotebook_kb.py`）就是 tagent 和 OpenNotebook 之间的全部后端耦合。

### 1.5 tagent 实际用到 OpenNotebook 的哪些接口（新版必须兼容的面）

后端 `opennotebook_kb.py`：

| 请求 | 用途 |
|---|---|
| `GET /health`、`GET /api/config` | 探活 |
| `GET /api/notebooks` | 列笔记本（取 id、name） |
| `POST /api/search` `{query, type: vector→失败再 text, limit, search_sources, search_notes, minimum_score}` | 检索；读结果的 `id`、`parent_id`、`title` |
| `GET /api/notes[?notebook_id=]`、`GET /api/sources[?notebook_id=&limit=100]` | 列某个笔记本的内容 |
| `GET /api/notes/{id}`、`GET /api/sources/{id}` | 取正文（`content` / `full_text`） |

前端 `src/lib/apis/opennotebook.ts`（经 `/opennotebook-api` 白名单）：建笔记本、建笔记、检索、读来源/笔记正文、列笔记本内容。

编号格式 `notebook:xxx`、`source:xxx`、`note:xxx`；鉴权头 `Authorization: Bearer <口令>`（同时带 `X-Password`）；错误体 `{"detail": "..."}`。

## 二、OpenNotebook（1.15.0）的架构

本机容器 `opennotebook-open_notebook-1` 里 `/app` 就是完整源码（仓库里的 `opennotebook/` 只有 docker-compose，没有源码）。

### 2.1 进程与依赖

```
浏览器 → Next.js 前端（8502）──/api/* 改写──→ FastAPI（5055）──→ SurrealDB（8000）
                                              └─ surreal-commands worker（后台任务：处理来源、嵌入、洞察、播客）
supervisord 管 api / worker / frontend 三个进程
```

后端依赖很重：fastapi、langchain 全家、langgraph、`esperanto`（24 家模型供应商的统一抽象）、`content-core`（网页/PDF/Office/音视频/YouTube 抽取，可选 docling、crawl4ai）、`ai-prompter`、`podcast-creator`、`surreal-commands`、`surrealdb`、tiktoken 等。

### 2.2 后端分块

| 模块 | 内容 |
|---|---|
| `api/main.py` | 启动时等数据库、自动跑 25 个迁移；中间件：口令（Bearer）→ 上传大小 → CORS；异常统一映射成 `{"detail"}` |
| `api/routers/`（24 个文件、约 150 个接口） | notebooks、notes、sources、search（检索 + ask 三段式问答）、chat、source_chat、insights、transformations、embedding、embedding_rebuild、commands、settings、config、auth、models（13）、credentials（14）、providers、capabilities、languages、podcasts（7）、episode_profiles（6）、speaker_profiles（6） |
| `open_notebook/domain/` | Notebook、Source、Note、SourceInsight、ChatSession、Transformation、Model、Credential、播客相关 |
| `open_notebook/graphs/` | source（抽取→保存→嵌入→变换）、ask（定策略→分头回答→汇总）、chat、source_chat、transformation、prompt |
| `commands/` | process_source、embed_source / embed_note / embed_insight、create_insight、run_transformation、rebuild_embeddings、播客生成 |
| `open_notebook/utils/` | 分块、嵌入、上下文拼装、token 计数 |
| 数据库 | SurrealDB：source、source_embedding、source_insight、note、notebook、关系表 reference（来源→笔记本）/ artifact（笔记→笔记本）/ refers_to（会话→笔记本或来源）、chat_session、transformation、model、credential、播客 4 张表、几条单例配置 |

检索：`fn::text_search` 用 BM25（分词器是 `blank,class,camel,punct + snowball(english)`，**对中文基本不起作用**——中文一整句被当成一个词）；`fn::vector_search` 用余弦相似度，来源按分块命中聚合，结果带 `matches`。

### 2.3 前端（Next.js 16 + React 19 + radix-ui + tanstack-query + zustand + i18next，254 个源文件）

页面：登录、笔记本列表、笔记本详情（来源栏 / 笔记栏 / 聊天栏三栏）、来源列表、来源详情（正文、洞察、来源聊天）、检索与问答、播客、变换（提示词模板管理）、模型与凭据、设置（抽取引擎、docling 选项）、高级（重建嵌入、系统信息）。14 种界面语言。

## 三、实际用了哪些（2026-11-11 只读核对现网 5055）

| 项 | 现网情况 |
|---|---|
| 笔记本 / 来源 / 笔记 | 都是 **0** |
| 嵌入模型 | **没配**（向量检索直接回 400 "Vector search requires an embedding model"，tagent 一直在走文本检索兜底） |
| 聊天会话、后台任务、播客节目 | 都是 0 |
| 变换（提示词模板） | 只有安装时自带的 6 个，没改过 |
| 抽取引擎 | 默认 auto；docling、crawl4ai 都没装 |
| 模型 | 走 tagent 的 `/v1/raw`（OpenNotebook 只是把请求转回 tagent） |

结论：真正用到的是「笔记本 / 来源 / 笔记的增删改查 + 检索」，以及给这几样配的界面；模型本来就是 tagent 提供的，供应商/凭据管理整套是多余的；播客、变换管理、抽取引擎配置、重建嵌入都没人用。

## 四、取舍

| 功能 | 处理 | 说明 |
|---|---|---|
| 笔记本增删改查、归档、删除预览与级联删除、最近浏览 | **保留** | 接口、字段、行为与原版一致 |
| 笔记增删改查（含 AI 笔记自动起标题） | **保留** | |
| 来源：文本 / 上传文件 / 网址，异步处理、状态、重试、下载 | **保留，抽取简化** | 文本、txt/md/csv/json/html/xml、PDF（pypdf）、docx（直接读 XML）、普通网页；不再支持音视频转写、YouTube 字幕、docling、crawl4ai |
| 检索（文本 + 向量） | **保留，重写** | SQLite FTS5 + 中文二元切词（原版对中文无效）；向量用和 tagent 同一个 `shibing624/text2vec-base-chinese`，本机缓存加载 |
| 问答（ask 三段式，SSE） | **保留** | 定策略 → 分头检索回答 → 汇总，事件格式不变 |
| 笔记本聊天、来源聊天 | **保留** | 模型统一走 tagent 的 OpenAI 兼容接口 |
| 洞察（对来源跑变换） | **保留** | 变换改为内置 6 个（中文提示词），只读 |
| 变换管理页、默认提示词、试验场 | **砍掉** | 没人改过模板 |
| 模型管理（13 个接口）、凭据（14 个）、供应商、能力探测 | **砍掉** | 模型配置改成环境变量；只留只读的 `GET /api/models`、`/api/models/defaults` 给界面上的模型下拉框显示 |
| 播客（节目、节目模板、说话人模板，19 个接口） | **砍掉** | |
| 设置页（抽取引擎、docling 选项、YouTube 语言） | **砍掉** | 只留只读的 `GET /api/settings`，添加来源对话框要读 |
| 高级页（重建嵌入、系统信息） | **砍掉** | 单条「重新嵌入」保留（来源详情里的按钮） |
| 后台任务列表、取消、注册表调试 | **砍掉** | 只留 `GET /api/commands/jobs/{id}` 给前端轮询 |
| SurrealDB、surreal-commands worker、supervisord | **砍掉** | 换成 SQLite + 进程内线程池 |
| 14 种界面语言 | 保留 | 只是翻译文件，删了反而改变界面 |

接口从约 150 个降到 60 个左右；后端依赖从「langchain 全家 + esperanto + content-core + surrealdb + podcast-creator」降到 flask、waitress、pydantic、httpx、numpy、pypdf、sentence-transformers（后几样 tagent 本来就装着）。

## 五、新版的组织

```
opennotebook新版/
  README.md               怎么跑、配置项、和原版的差别
  docs/架构分析与拆分方案.md
  backend/                Flask + waitress，按 tagent 的分层手工重写
    main.py
    app/
      config.py           唯一读环境变量的地方
      factory.py          create_app
      container.py        装配：仓储 → 嵌入/模型客户端 → 各 service
      errors.py           业务异常（带状态码），api 层统一转 {"detail"}
      api/                notebooks / notes / sources / search / chat / source_chat / insights / meta
      service/            notebook / note / source / search / ask / chat / insight / jobs
      repository/         database（连接+迁移）/ notebooks / notes / sources / chats / jobs / index
      rag/                分块、中文切词、嵌入模型、向量矩阵缓存
      infra/              模型客户端（OpenAI 兼容）、内容抽取、网址安全检查
      prompts/            聊天 / 问答 / 起标题 / 内置变换
      schema/             请求体 pydantic 模型
      util/               编号、时间格式
    tools/check_architecture.py   和 tagent 同一套 6 条规则
    tests/
  frontend/               原版 Next.js 前端，删掉砍掉的页面，其余组件和样式不动
```

### 5.1 和 tagent 分层的对应

| 原版 | 新版 | 将来并进 tagent 的位置 |
|---|---|---|
| `api/routers/*` | `app/api/*`（Flask 蓝图） | `basic-agent/app/api/notebook_*.py` |
| `open_notebook/domain/*` + `commands/*` | `app/service/*` | `basic-agent/app/service/` |
| SurrealDB 查询 | `app/repository/*`（SQLite，写法照 `learning_store.py`） | `basic-agent/app/repository/` |
| `utils/chunking`、`embedding`、`fn::*_search` | `app/rag/*` + `repository/index.py` | `basic-agent/app/rag/`，可和本地知识库共用嵌入模型 |
| `graphs/ask`、`chat`、`source_chat` | `app/service/ask_service.py`、`chat_service.py` | 换成 tagent 的 answer 图 |
| esperanto 模型抽象 | `app/infra/llm_client.py`（只认 OpenAI 兼容接口） | 直接用 tagent 的 `client_factory` |
| surreal-commands worker | `app/service/jobs.py`（进程内线程池 + jobs 表） | 同 |

### 5.2 数据（SQLite，`~/Library/Application Support/OpenNotebookLite/notebook.sqlite3`，可配）

`notebooks`、`sources`、`notes`、`source_notebooks`（原 reference）、`note_notebooks`（原 artifact）、`chunks`（原 source_embedding，向量存 float32 二进制）、`insights`、`chat_sessions`、`chat_messages`、`jobs`、`search_fts`（FTS5 全文索引）。编号仍是 `表名:20位小写字母数字`，时间对外仍是原版的 `2026-11-11 08:00:00.000000+00:00` 格式，前端和 tagent 都不用改。

### 5.3 检索

- **文本**：入库时把文字切成「英文单词 + 中文单字 + 中文相邻两字」，存进 FTS5；查询按同样规则切（中文用两字词），BM25 排序。来源标题、分块、洞察、笔记标题和正文都进索引；返回 `{id, parent_id, title, relevance}`，和原版一样按条目取最高分。
- **向量**：分块、洞察、笔记各存一份向量；查询时在内存矩阵上算余弦（矩阵按写入版本号缓存）；返回 `{id, parent_id, title, similarity, matches}`。嵌入模型加载不了就回原版同样的 400，tagent 会自动改用文本检索。
- 给了 `notebook_ids` 只在这些笔记本关联的来源和笔记里找。

### 5.4 后台任务

上传/网址来源默认异步：先建记录、立刻关联笔记本、回 `status: "new"`，后台线程做「抽取 → 分块 → 全文索引 → 嵌入 → 跑选中的变换」，状态写 `jobs` 表（new / queued / running / completed / failed），前端照旧轮询。服务重启时把没跑完的任务标成失败（可点重试）。

### 5.5 模型

`ON_LLM_BASE_URL`（默认 `http://127.0.0.1:5001/v1/raw`，即 tagent 的原样转发通道）、`ON_LLM_MODEL`、`ON_LLM_API_KEY`。聊天、问答、洞察、AI 笔记起标题都走它；没配通时接口回 502 并写明原因，其余功能不受影响。

## 六、前端怎么保持「视觉上相同」

- 直接用原版前端源码（同一套组件、同一份 `globals.css`、同一套 shadcn/radix 组件、同样的 14 种语言），不重画。
- 只删砍掉功能的页面（播客、变换、模型、设置、高级、设计稿调试页）和指向它们的入口：侧边栏「创作」「管理」两组、新建菜单里的「播客」、命令面板里的对应项、顶部的「未配置模型」横幅。
- 保留的页面（登录、笔记本列表、笔记本详情三栏、来源列表、来源详情、检索与问答）组件不改，样式与原版逐像素一致。
- 模型下拉框仍在，只显示后端配置的那一个模型。

## 七、并进 tagent（已做）

代码在 `basic-agent/app/` 下各层的 `notebook/` 子包里（接口仍是 `/api/notebooks` 这一套，避免和 tagent 已有路由撞名）。
本机地址的检索走 `InProcessNotebookKnowledgeBase`，不再 HTTP 打 5055。嵌入模型和本地知识库共用一份。
聊天、问答仍用笔记本原来的事件格式（页面认这套），模型调用改成进程内使用 tagent 已登记的模型。
页面还是 `opennotebook新版/frontend/`，启动脚本拉到 8502；5055 由 basic-agent 再听一个端口。

原来的四步：

1. 把 `backend/app/*` 各层文件按 5.1 的表搬进 `basic-agent/app/` 对应层，蓝图挂到 `/api/notebook/*` 或保持 `/api/*`；
2. `opennotebook_kb.py` 从「HTTP 调 5055」换成「直接调 service」，省掉一跳；
3. 嵌入模型和本地知识库共用一个实例；聊天、问答换成 tagent 的 answer 图；
4. 前端 `/notebook` 页面的 iframe 指向新版前端，或者把几个页面用 Svelte 重写进 tagentnote。

## 八、实现与验证记录（2026-11-11）

### 实现中发现并处理的问题

| 问题 | 处理 |
|---|---|
| 原版前端默认让浏览器**直连「页面主机名 + :5055」**（`/config` 自动拼），新版前端起在别的端口时，会悄悄连到本机正在跑的原版后端 | 验证时给前端设 `API_URL`；README 写明两条连接路径（直连用 `API_URL`，SSE 和 `/api/*` 改写用 `INTERNAL_API_URL`） |
| 浏览器直连后端时预检请求带 `Cache-Control` 头，只放行固定几个头会被拦，登录页显示「无法连接」 | 跨域预检照原版 `allow_headers=["*"]`：要什么头放什么头（有测试） |
| SQLite 的 BM25 在资料少时把常见词的 IDF 压到 1e-6，检索页相关度全显示 0.00 | 相关度改为「命中查询词的比例」，BM25 只用于同分排序（有测试） |
| tagent 到 DeepSeek 的 TLS 连接时好时坏，问答第四次调用常碰上一次 502 | 模型客户端对 429/5xx/连接错误自动重试 2 次（原版 LangChain 客户端默认也重试），实测两次 502 都被救回（有测试） |
| 测试收尾关库时后台任务线程还在用连接，sqlite 段错误 | 关库只关本线程和已结束线程的连接；关任务池时等正在跑的任务最多 10 秒 |
| Next 16 默认的 Turbopack 在含中文的路径下构建报 `next/font/google queries have exactly one entry`（英文路径下同一份代码能构建，已对照验证） | `dev`/`build` 改用 `--webpack` |
| 原版有两个页面都映射到 `/`（都只是跳转到 `/notebooks`），webpack 构建时报追踪警告 | 删掉被遮住的 `(dashboard)/page.tsx` |
| 构建时 Next 往上层目录找锁文件、碰到家目录里一个无关的 `package-lock.json` 发警告 | `next.config.ts` 显式设 `outputFileTracingRoot` |
| 前端自带的「没用到的翻译键」测试：砍掉页面后 454 个键没人用 | 14 种语言文件里同步删掉这 454 个键（脚本按键路径删，结构不动） |
| 原版代码里 4 条 react-hooks lint 警告 | 把依赖数组里的翻译调用提成变量，行为不变 |

### 验证结果
