## 一、出题质量（这次最值得说的一条）

**以前什么样**：填「排队论」出来的卷子，21 题里有 20 题出自论文细节——考「主路常数 m 值为多少」「围合式小区改善率 γ1 约为多少」这种某篇论文独有的数字。题干里大量出现「根据材料」「如图 4.9 所示」，而学生根本没见过那些材料。闪卡也一样，还出现过把答案直接写在题干里的卡。

**根子在两处**：取材时 14 篇论文按数量远多于教材，短主题会被论文片段淹没；出题时也没有任何规则拦着它考细枝末节。

**四处一起治**：

1. **取材按来源控比例**——教材至少占六成，论文只做补充；教材命中不够时才让论文补满。
2. **出题前先定考点**——三段（填空 / 选择 / 大题）是并发出的，互相看不见，以前会出现填空问「ρ 的计算公式」、选择又问「ρ 的表达式」。现在先统一定好考点再切给三段，各管各的。
3. **出题加硬约束**——题目必须自足（不准出现「材料中」「如图」）、不考某篇论文独有的数值、答案不许写在题干里。
4. **出完再过一道闸**——违规的题直接删掉，删完不够数才重出。

**现在什么样**：同样填「排队论」，20 题全部落在课程核心内容上（M/M/1、服务强度、Little 公式、仿真时钟推进、逆变换抽样、置信区间等），指代材料的题 0 道。每卷重复考点从约 1.8 处降到约 1.1 处。

另外三道大题以前全是「给定 λ 和 μ 求指标」只换数字，等于只考了一道；现在固定是计算、建模设计、对比分析各一道。

> 实测：8 次出卷全部成功，中位 9.07 秒（v1.0.0 是 6.77 秒，代价见「四、速度」）。

## 二、答疑

**能接着上文问了。** 以前每次提问只把当前这一句发给模型，问「那它的前提呢」模型不知道「它」指什么。更糟的是**找参考材料时也只拿这一句去找**，实测找到的是供应链和疫情相关的论文——「前提」撞上了论文里的「Pareto 前沿」。回答看着像对的，但依据全错，一旦问到教材里才有的内容就会露馅。

现在会带上前几轮对话，并且找材料时自动把上文的话题词补进去。同一句追问，现在找到的是课程教材。

**设置里的参数真的生效了。** 温度、Top P、最大长度以前调了没有任何反应——前端发出去了，后端压根没读。现在接通了。面板上其余不起作用的开关已经收起来，不再给调了没用的滑块。

**追问建议和标签。** 长问题引用时会在合适位置截断并加省略号（以前硬切成半截词）；`M/M/1` 这类记号不会再被当成标点拆散丢掉。

## 四、速度

同一台机器、新旧版背靠背实测（不调模型的接口各 30 次，出题各 8 次，取中位）：

| | v1.0.0 | 现在 | |
|---|---|---|---|
| `/health`、`/v1/models` | 0.4~0.5 ms | 0.4 ms | 不变 |
| 知识来源自检（笔记本在线） | 30.5 ms | **0.4 ms** | 快 75 倍 |
| 知识来源自检（笔记本挂起） | **5.01 s** | **0.5 ms** | 快 1 万倍 |
| 答疑：收到请求 → 开始调模型 | — | 16 ms | |
| 闪卡出题 | 3.68 s（8 次失败 1） | 3.91 s（0 失败） | 持平 |
| 整卷出题 | **6.77 s** | **9.07 s** | **慢 2.3 秒** |

**不调模型的接口都在 1 毫秒以内**。自检接口原来每次都现场去问笔记本服务，服务挂起时每次要卡 5 秒；现在改成后台定时去问，接口直接返回上次的结果。

**整卷比 v1.0.0 慢了 2.3 秒，这是出题质量修复的代价。** 逐段计时找到两个原因：

1. 取材换成教材之后，大题从「论文概念题」变成了「给定 λ、μ 求指标」这类计算题，模型会把参考答案逐步展开推导，大题段输出长了近一半（2144 → 3167 字），而大题段正是三段里决定总耗时的那段。**已处理**：参考答案只写要点和关键算式（判分靠的是逐条勾评分要点，不需要完整解题过程），大题段 11.5 → 7.9 秒。
2. 「先定考点」那一轮原本串行地挡在三段前面。**已处理**：大题本来就靠「计算 / 建模 / 对比各一道」保证不重复，不需要等规划，改成从 0 秒起步与规划并行。

两项合计把整卷从 11.9 秒拉回 9.07 秒。剩下的 2.3 秒主要是大题段一次要出三道（约 8.5 秒）；下一步会把三类大题拆成三路并发。

另外：
- 答疑页每次打开不再把笔记本列表整轮重发，十几秒内复用；
- 每次提问不再额外多打一次笔记本检索，只在后端没给出处时才打。

## 六、具体做法

给要接手或要改这块的人看。

### 答疑：两步拆成三步

原来是 `检索 → 生成`。问题出在「检索」用的是原封不动的那一句——追问「那它的前提呢」里没有一个可检索的实词，于是撞上了无关论文。

现在是 `理解问题 → 检索 → 生成`，每步一个节点（`app/rag/graph.py`）。

「理解问题」这一步**不调模型**，否则每次追问都要多等一轮，而这一层的目标是「除了模型本身，用户感觉不到延迟」。判断逻辑在 `app/rag/followup.py`：

- 句子里有指代词（它 / 这个 / 该 / 上述 / 前者…），或整句就是一句光杆追问（为什么 / 具体点 / 举个例子 / 继续…），就认定它离开上文检索不出东西；
- 认定了就**往回找上一个自己能独立检索的用户提问**，把它拼到检索词前面。连着追问好几句时会一直回溯，不会拼上另一句指代。

有两个坑写在代码注释里了：一是别把「怎么 / 如何 / 为什么」当指代词（「Little 公式怎么推导」是完全自足的）；二是别用「字数少就算追问」来判（中文实词密度高，「什么是排队论」去掉虚词只剩 5 个字，误判之后会拿上一个话题的材料来答，比不补还糟）。

流式回答不走这张图（它要逐块吐字），但**调的是同一个函数**——两条路必须按同一个检索词取材，否则同一个问题换个开关、给出的依据就变了。

### 出题：先定考点，再分头出，出完再筛

原来是三段（填空 / 选择 / 大题）并发直接出题。三段互相看不见，于是填空问「ρ 的计算公式」、选择又问「ρ 的表达式」。

现在的顺序（`app/service/exam_service.py`）：

```
大题  ─────────────────────────────┐   从 0 秒起步，不等规划
定考点 ──→ 切成两份 ─┬─ 填空 ──────┤
                    └─ 选择 ──────┴─→ 过滤 → 组卷
```

1. **定考点**：先用一次调用列出填空和选择要考的点，并要求它「宁可少给也不要硬凑」——硬凑会逼出一堆近义项（「L 与 W 的公式」和「Lq 与 Wq 的公式」）。
2. **切分**：考点**轮流发**给填空和选择，不是按顺序切块——模型习惯把最核心的排在前面，顺序切块会让填空独占全部核心考点。某段分到的考点少于它的题数下限时**不给它清单**，让它自由出题，否则会卡在下限上。
3. **大题不等规划**：大题是三段里最慢的（约 8 秒），又最不需要规划——三道大题靠「计算 / 建模 / 对比各一道」本来就不重复，撞考点出在填空和选择之间。让它从 0 秒起步和规划并行，总耗时就从「规划 + 大题」变成「大题」和「规划 + 填空」里较长的那个。
4. **过滤**：删掉指代材料的、答案写在题干里的（`app/schema/exam_quality.py`）。
5. **组卷**：裁到规定题数。

另外，大题的**参考答案只写要点和关键算式**、控制在 300 字内。取材换成教材后大题多是计算题，不加这条时模型会逐步展开推导，输出长了近一半——而判分靠的是逐条勾评分要点，参考答案只是对照依据，用不着完整解题过程。

关键的一条是**留余量**：分段草稿允许模型多出几道，过滤删掉之后再裁。没有余量时删掉两三道就跌破下限、整段重出、最后报错。

取材那一步（`app/rag/knowledge_base.py`）另有两个要点：候选池要**比最终用的多**，否则按来源配比就没有可挑的余地；挑出来之后要**交错排列**，因为下游还会按条数和字数再截一刀，不交错的话配比挑进来的教材会被整段截掉。

### 判分：能本机算的不调模型

闪卡的对错、整卷的填空与选择都在本机判。只有大题和小论文走模型，而且**逐句批注是点开才算**——不点就不花这一轮，所以不会拖慢交卷。

### 正在做：答疑和出题/批改合成一套（为文件编辑铺路）

下一轮要加「文件编辑」——编辑用户上传的文件，形态是**模型给修改建议、用户逐条采纳**。

原来每条链路在 service 里各写一套：「算超时 → 取模型 → 调用 → 校验」这一串抄了 7 份，并发出题抄了 3 份。文件编辑照老样子只能抄第四份，所以先把它们收成一套共用积木（`app/agent/`）：

```
app/agent/
  runtime.py   一次运行的依赖（模型、知识库、截止时间）和超时算法
  nodes.py     共用节点：带预算、带校验的一次模型调用
  graphs/      每种能力一张图，用上面的节点拼出来
```

对外接口一个都不改，前端不用动；service 只剩一层门面：拿闸门 → 准备依赖 → 跑图。

文件编辑会直接复用**逐句批注**那套：它已经解决了「模型的意见怎么准确落回原文」——先切句编号、存好每句在原文里的位置，模型只回编号，高亮时查表。修改建议就是批注再加一个「替换成什么」。

进度：

| 步 | 内容 | 状态 |
|---|---|---|
| 0 | 定位并修掉整卷变慢 | 已完成（11.9 → 9.1 秒） |
| 1 | 共用积木 `app/agent/` | 已完成 |
| 2 | 逐句批注改走图 | 已完成 |
| 3~7 | 小论文批改、闪卡、整卷、判卷、答疑依次迁移 | 进行中 |
| 8 | 文件编辑的骨架：给一段文字 → 返回带位置的修改建议 → 应用用户采纳的几条 | 待做 |

文件存哪还没定：后端目前**完全没有文件存储**；输入框的「上传文件」是个空壳，只记了文件名、内容没读。存进笔记本服务还是后端自建，要先确认笔记本服务能不能改写已上传的内容，这是下一轮的第一件事。

## 八、已知问题

- **手机上不好用**：375 像素宽时侧栏默认展开把对话挤成细条；收起后顶栏有 5 个按钮在屏幕外，页面又不能横向滚动。这轮没动。

- 同一张卷子里偶尔仍有一处考点重复（约每卷 1 处）。
- 论文任务栏会挡住题目卡片上沿；欢迎页的浮标压住比赛名称。
- 题干里出现四个字符以内的英文缩写（如 FIFO）而答案正是它时，过滤器不会判为泄漏。这是有意放宽的——收紧会误删大量合格题，反而导致整次出卷失败。
