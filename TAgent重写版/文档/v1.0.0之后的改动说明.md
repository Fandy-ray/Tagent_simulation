## 一、出题质量（这次最值得说的一条）

**以前什么样**：填「排队论」出来的卷子，21 题里有 20 题出自论文细节——考「主路常数 m 值为多少」「围合式小区改善率 γ1 约为多少」这种某篇论文独有的数字。题干里大量出现「根据材料」「如图 4.9 所示」，而学生根本没见过那些材料。闪卡也一样，还出现过把答案直接写在题干里的卡。

**根子在两处**：取材时 14 篇论文按数量远多于教材，短主题会被论文片段淹没；出题时也没有任何规则拦着它考细枝末节。

**四处一起治**：

1. **取材按来源控比例**——教材至少占六成，论文只做补充；教材命中不够时才让论文补满。
2. **出题前先定考点**——三段（填空 / 选择 / 大题）是并发出的，互相看不见，以前会出现填空问「ρ 的计算公式」、选择又问「ρ 的表达式」。现在先统一定好考点再切给三段，各管各的。
3. **出题加硬约束**——题目必须自足（不准出现「材料中」「如图」）、不考某篇论文独有的数值、答案不许写在题干里。
4. **出完再过一道闸**——违规的题直接删掉，删完不够数才重出。

**现在什么样**：同样填「排队论」，20 题全部落在课程核心内容上（M/M/1、服务强度、Little 公式、仿真时钟推进、逆变换抽样、置信区间等），指代材料的题 0 道。每卷重复考点从约 1.8 处降到约 1.1 处。

另外三道大题以前全是「给定 λ 和 μ 求指标」只换数字，等于只考了一道；现在固定是计算、建模设计、对比分析各一道。

> 实测：8 次出卷全部成功，中位 8.23 秒（v1.0.0 是 6.77 秒，代价见「五、速度」）。

## 二、答疑

**能接着上文问了。** 以前每次提问只把当前这一句发给模型，问「那它的前提呢」模型不知道「它」指什么。更糟的是**找参考材料时也只拿这一句去找**，实测找到的是供应链和疫情相关的论文——「前提」撞上了论文里的「Pareto 前沿」。回答看着像对的，但依据全错，一旦问到教材里才有的内容就会露馅。

现在会带上前几轮对话，并且找材料时自动把上文的话题词补进去。同一句追问，现在找到的是课程教材。

**设置里的参数真的生效了。** 温度、Top P、最大长度以前调了没有任何反应——前端发出去了，后端压根没读。现在接通了。面板上其余不起作用的开关已经收起来，不再给调了没用的滑块。

**回答被截断会说一声。** 回答到了长度上限（「控制」里的 max_tokens，或模型自己的上限）时，以前停在半截、常常还留着半个公式符号，看不出是被截了。现在末尾补一句「回答到了长度上限……可以调大 max_tokens 再重新生成」，截在公式中间时先把公式收尾。

**追问建议和标签。** 长问题引用时会在合适位置截断并加省略号（以前硬切成半截词）；`M/M/1` 这类记号不会再被当成标点拆散丢掉；追问「那它的前提呢」之后，建议不再写成「请更详细地解释「那它的前提呢」」，标签也不再出「#那它」「#什么」这种词。

## 三、判卷、出卷和接口的几个老问题

- **判卷约一半失败。** 模型判大题时常在每条结果里多写几个字段（比如把「2/3≈0.7」这种算式另起一栏），而判分结果的格式检查是「多一个字段都不行」，两次都不合格就整卷报错。同一张卷实测 10 次里约 5 次失败。现在多写的字段直接丢掉，题号、分数照样严格查；修后 12 次全部判完。
- **不存在的地址回「服务出错」。** 访问不存在的路径、用错请求方法，以前一律回 500「服务内部错误」，还记一条错误日志。现在照实回 404 / 405。
- **知识来源挂了整张卷判不出来。** 判大题时会顺手查几段课程材料当参考；只配了一个知识来源时它一挂，整次判卷就失败。现在查不到就不带材料判（评分要点和参考答案才是依据）。
- **选了个空笔记本还照样出卷。** 闪卡会当场提示「所选知识范围里没有可出题的材料」，整卷却照样去调模型，白等一轮多半报错。现在和闪卡一样当场提示。

## 四、界面与交互

- 交卷前会提醒还有几题没答（以前只答 3 题也能直接交，误触就前功尽弃）。
- 闪卡刷到一半退出会先问一句（以前进度直接丢）。
- 闪卡答错后主按钮变成「进重练」，「其实我答对了」降为次要按钮——错题不会再顺手点「会了」漏出重练队列。
- 切换「课程答疑 / 论文助手」时会说明对话存去了哪（以前对话清空，容易以为聊没了）。
- 整卷底部的题号栏改成换行，21 个题号全看得见（以前首尾被横向滚动条挤出视野，点不到）。
- 论文助手新任务默认从「选题与大纲」开始（以前写死在「实验设计」，和卡片上「先写题目，再分章节」自相矛盾）。
- 「填入范例」会把原来的题目一并说出来，方便放回去（以前一声不响换掉）。
- 平台名称统一；中文界面里的 `Exam completed` / `Deck cleared` 改成中文；「WebUI 设置」改名；回答头部显示登记的模型名而不是小写 id。
- 没绑笔记本时不再说「按当前笔记本出题」。
- 填空题上方的提示句如果只是把题干又抄了一遍，就不再显示（以前闪卡和整卷几乎每道填空都是同一句话出现两遍）。
- **手机上能用了。** 以前 375 像素宽时侧栏默认展开，把对话挤成一条细缝，收起后顶栏的按钮又挤出屏幕点不到。现在窄屏上侧栏盖在内容上、默认收起，点旁边或选完对话就收起；顶栏按自身宽度排，放不下就折成两行，所有按钮都点得到（「临时对话」「数据」在窄屏上收进了设置）。
- 打开右侧「控制」面板时，「课程答疑 / 论文助手」切换按钮不再消失（以前要先关面板才能切）。
- 出题、批改这类一次性出来的长卡片，出来时卡片开头对齐在可视区顶上，不再被滚到论文任务栏后面、看着像被挡住。
- 欢迎页的装饰节点挪到外圈，不再压住大标题和比赛名称。

## 五、速度

同一台机器、新旧版背靠背实测（不调模型的接口各 30 次，出题各 8 次，取中位）：

| | v1.0.0 | 现在 | |
|---|---|---|---|
| `/health`、`/v1/models` | 0.4~0.5 ms | 0.2~0.3 ms | 不变 |
| 知识来源自检（笔记本在线） | 30.5 ms | **0.3 ms** | 快 100 倍 |
| 知识来源自检（笔记本挂起） | **5.01 s** | **0.5 ms** | 快 1 万倍 |
| 答疑：收到请求 → 开始调模型 | — | 16 ms（走图只多 0.25 ms） | |
| 闪卡出题 | 3.68 s（8 次失败 1） | 3.83 s（0 失败） | 持平 |
| 整卷出题 | **6.77 s** | **8.23 s** | **慢 1.5 秒** |
| 判卷（3 批送模型） | 一批接一批 4.32 s | **并发 1.68 s** | 快 2.6 倍 |

> 出题的秒数受上游当时的快慢影响很大：同一份代码隔一小时复测，整卷中位 9.3～10.8 秒、闪卡 4.5 秒。逐段时间线和上表那次一模一样（大题和定考点同时起步，填空、选择紧跟定考点），只是每一段都慢了一些；同一时刻单调一次大题段仍是 7.5 秒左右。所以比较快慢一定要像第 0 步那样，新旧版在同一时段交替跑，别拿不同时段的数字直接比。

**不调模型的接口都在 1 毫秒以内**。自检接口原来每次都现场去问笔记本服务，服务挂起时每次要卡 5 秒；现在改成后台定时去问，接口直接返回上次的结果。

**整卷比 v1.0.0 慢了 1.5 秒，这是出题质量修复的代价。** 逐段计时找到两个原因：

1. 取材换成教材之后，大题从「论文概念题」变成了「给定 λ、μ 求指标」这类计算题，模型会把参考答案逐步展开推导，大题段输出长了近一半（2144 → 3167 字），而大题段正是三段里决定总耗时的那段。**已处理**：参考答案只写要点和关键算式（判分靠的是逐条勾评分要点，不需要完整解题过程），大题段 11.5 → 7.9 秒。
2. 「先定考点」那一轮原本串行地挡在三段前面。**已处理**：大题本来就靠「计算 / 建模 / 对比各一道」保证不重复，不需要等规划，改成从 0 秒起步与规划并行。

两项合计把整卷从 11.9 秒拉回 8.2 秒左右。剩下的 1.5 秒基本就是「先定考点」那一轮。

**试过、没采用：把三道大题拆成三次同时出。** 单看大题段确实短了，放进整条流程反而更慢（交替各跑 8 次：一次出三道 8.61 秒，拆成三次 9.71 秒）——多出来的请求和「定考点」挤在同一时刻，定考点从 1.9 秒拖到 4~6 秒，而填空、选择要等它。同时请求越多，每一路越慢，并发不是免费的。

另外：
- 判卷的几批原来一批接一批，现在同时发，见上表；
- 答疑页每次打开不再把笔记本列表整轮重发，十几秒内复用；
- 每次提问不再额外多打一次笔记本检索，只在后端没给出处时才打。

## 七、具体做法

给要接手或要改这块的人看。

### 答疑：两步拆成三步

原来是 `检索 → 生成`。问题出在「检索」用的是原封不动的那一句——追问「那它的前提呢」里没有一个可检索的实词，于是撞上了无关论文。

现在是 `理解问题 → 检索 → 生成`，每步一个节点（`app/agent/graphs/answer.py`）。

「理解问题」这一步**不调模型**，否则每次追问都要多等一轮，而这一层的目标是「除了模型本身，用户感觉不到延迟」。判断逻辑在 `app/rag/followup.py`：

- 句子里有指代词（它 / 这个 / 该 / 上述 / 前者…），或整句就是一句光杆追问（为什么 / 具体点 / 举个例子 / 继续…），就认定它离开上文检索不出东西；
- 认定了就**往回找上一个自己能独立检索的用户提问**，把它拼到检索词前面。连着追问好几句时会一直回溯，不会拼上另一句指代。

有两个坑写在代码注释里了：一是别把「怎么 / 如何 / 为什么」当指代词（「Little 公式怎么推导」是完全自足的）；二是别用「字数少就算追问」来判（中文实词密度高，「什么是排队论」去掉虚词只剩 5 个字，误判之后会拿上一个话题的材料来答，比不补还糟）。

流式和非流式走同一张图：两条路必须按同一个检索词取材，否则同一个问题换个开关、给出的依据就变了。区别只在最后一步——流式检索完就出图，由外面拿着模型的输出逐块往前端送，原因见下面「怎么拆的」第 4 条。

### 出题：先定考点，再分头出，出完再筛

原来是三段（填空 / 选择 / 大题）并发直接出题。三段互相看不见，于是填空问「ρ 的计算公式」、选择又问「ρ 的表达式」。

现在的顺序（`app/agent/graphs/exam.py`）：

```
取材 ─┬─ 大题 ─────────────────────────────┐   从 0 秒起步，不等规划
      └─ 定考点 ──→ 切成两份 ─┬─ 填空 ──────┤
                             └─ 选择 ──────┴─→ 过滤 → 组卷
```

1. **定考点**：先用一次调用列出填空和选择要考的点，并要求它「宁可少给也不要硬凑」——硬凑会逼出一堆近义项（「L 与 W 的公式」和「Lq 与 Wq 的公式」）。
2. **切分**：考点**轮流发**给填空和选择，不是按顺序切块——模型习惯把最核心的排在前面，顺序切块会让填空独占全部核心考点。某段分到的考点少于它的题数下限时**不给它清单**，让它自由出题，否则会卡在下限上。
3. **大题不等规划**：大题是三段里最慢的（约 8 秒），又最不需要规划——三道大题靠「计算 / 建模 / 对比各一道」本来就不重复，撞考点出在填空和选择之间。让它从 0 秒起步和规划并行，总耗时就从「规划 + 大题」变成「大题」和「规划 + 填空」里较长的那个。
4. **过滤**：删掉指代材料的、答案写在题干里的（`app/schema/exam_quality.py`）。
5. **组卷**：裁到规定题数。

另外，大题的**参考答案只写要点和关键算式**、控制在 300 字内。取材换成教材后大题多是计算题，不加这条时模型会逐步展开推导，输出长了近一半——而判分靠的是逐条勾评分要点，参考答案只是对照依据，用不着完整解题过程。

关键的一条是**留余量**：分段草稿允许模型多出几道，过滤删掉之后再裁。没有余量时删掉两三道就跌破下限、整段重出、最后报错。

取材那一步（`app/rag/knowledge_base.py`）另有两个要点：候选池要**比最终用的多**，否则按来源配比就没有可挑的余地；挑出来之后要**交错排列**，因为下游还会按条数和字数再截一刀，不交错的话配比挑进来的教材会被整段截掉。

### 判分：能本机算的不调模型

闪卡的对错、整卷的填空与选择都在本机判。只有大题和语义要判的填空才送模型，按题型切成小批**同时发**（`app/agent/graphs/grade.py`）；**逐句批注是点开才算**——不点就不花这一轮，所以不会拖慢交卷。

### 答疑和出题/批改合成一套（为文件编辑铺路）

下一轮要加「文件编辑」——编辑用户上传的文件，形态是**模型给修改建议、用户逐条采纳**。原来每条链路在 service 里各写一套：「算超时 → 取模型 → 调用 → 校验」这一串抄了 7 份，并发出题抄了 3 份，照老样子文件编辑只能抄第四份。所以先把它们收成一套。

**怎么拆的**（`app/agent/`）：

```
app/agent/
  runtime.py   一次运行要用的东西：模型、知识库、截止时间、可调参数；超时怎么算
  nodes.py     共用的一步：带预算、带校验地调一次模型；检索拼材料
  graphs/      每种能力一张图
    answer.py    答疑：理解问题 → 检索 → 生成
    exam.py      整卷：取材 → 大题 ∥（定考点 → 填空 ∥ 选择）→ 组卷
    flash.py     闪卡：取材切片 → 几片同时出 → 删坏卡、去重、交错
    grade.py     判卷：给大题配材料 → 几批同时判
    essay.py     小论文：取材 → 三个维度同时打分 → 被点名的段落才逐句批注
    annotate.py  逐句批注
    edit.py      文件编辑（这轮只铺路）
```

service 那一层只剩门面：检查输入 → 拿闸门 → 准备依赖 → 跑图 → 整理结果。对外接口一个没改，前端不用动。

拆的时候守的几条规矩，都是实测出来的：

1. **模型、知识库这些对象不放进流程的数据里**，随一次运行单独传给每一步。它们不能也不该被逐步复制。
2. **整次运行共用一个截止时间**，几路同时跑时谁都可以用满剩下的时间；以前判卷要把预算按批数切开，改成同时发之后就不用了。
3. **要等别人的放进一张小图里。** 图是一轮一轮推进的，同一轮的全部做完才进下一轮。「定考点」要是和大题同在一轮，填空、选择就得等最慢的大题做完才开始。所以「定考点 → 填空 ∥ 选择」打包成一张子图，和大题并排跑，互不等待。
4. **逐字往外吐的那一步不放进图里。** 实测图在中途被关掉时会等那一步自己跑完：学生点了「停止」，模型照样生成到底、照样计费。所以答疑的流式只让图做前两步，生成由外面拿着模型的输出流来送，一关就断。
5. **闸门留在门面里**，按「一次出卷 / 一次批改」拿一个名额，图里不再拿。
6. 几路同时跑时**一路出错，会等其余几路结束再报错**（和原来一样），不会出现名额已经还了、模型还在后台跑的情况。

每条规矩都有测试钉着（谁把并发改回串行、把子图拆回平铺、把逐字输出挪进图里，测试会红），测试里也验证过这些写法反过来确实会挂。

**加一条新能力**照这个顺序：在 `nodes.py` 里找能复用的一步 → 在 `graphs/` 里新建一张图 → service 里加一个门面方法（拿闸门、建依赖、跑图）→ 路由。

**文件编辑这轮做到的**（`app/agent/graphs/edit.py`、`app/schema/edit.py`）：给一段文字 → 返回修改建议 → 把用户采纳的几条改回原文。

- 一条修改建议 = 一条批注（落在哪一句、为什么改）+ 改成什么（整句）。直接沿用逐句批注那套：先切句编号、存好每句在原文里的位置，**模型只回编号**，从不回原文片段或位置，查表就能落回原文；
- 改回原文**从后往前**替换，前面的位置才不会被后面的改动挪动；原文在给建议之后又被改过、或两条建议改的范围重叠，就直接拒绝，不去猜；
- 要建议却失败时报错，不回空列表——用户是专门来要建议的，空列表等于告诉他「没什么好改的」。

还没接路由、上传、存储和界面。文件存哪还没定：后端目前**完全没有文件存储**；输入框的「上传文件」是个空壳，只记了文件名、内容没读。存进笔记本服务还是后端自建，要先确认笔记本服务能不能改写已上传的内容，这是下一轮的第一件事。

## 九、已知问题

下面这几条都不是代码缺陷，是设计取舍、模型本身或本机环境的问题：

- **登记模型需要管理口令**，口令在 `TAgent重写版/.env.runtime` 里，对非技术同学门槛偏高。这是有意的：登记模型要填 Key，不能谁都能改。
- 同一张卷子里偶尔仍有一处考点重复（约每卷 1 处），是模型出题的波动；先定考点之后已经从约 1.8 处降下来了。
- 题干里出现四个字符以内的英文缩写（如 FIFO）而答案正是它时，过滤器不会判为泄漏。这是有意放宽的——收紧会误删大量合格题，反而导致整次出卷失败。
- **本机开着代理时偶尔连不上模型。** 后端对外请求会走系统代理（本机是 17897 端口），代理偶发中途断开，单次调用会报「连不上模型服务」；会自动重试一次，连着两次才失败。DeepSeek 在国内可直连，可以把 `api.deepseek.com` 加进 `NO_PROXY`。
- 同一份作答重判，大题得分会有几分出入（实测同一张卷 12 次在 25~32 分之间），是模型自身的波动。
