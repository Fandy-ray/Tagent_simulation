## 一、出题质量（这次最值得说的一条）

**以前什么样**：填「排队论」出来的卷子，21 题里有 20 题出自论文细节——考「主路常数 m 值为多少」「围合式小区改善率 γ1 约为多少」这种某篇论文独有的数字。题干里大量出现「根据材料」「如图 4.9 所示」，而学生根本没见过那些材料。闪卡也一样，还出现过把答案直接写在题干里的卡。

**根子在两处**：取材时 14 篇论文按数量远多于教材，短主题会被论文片段淹没；出题时也没有任何规则拦着它考细枝末节。

**四处一起治**：

1. **取材按来源控比例**——教材至少占六成，论文只做补充；教材命中不够时才让论文补满。**填空、选择、闪卡只拿教材片段**，论文片段只给大题当应用场景。
2. **几路分头出、各管一块**——题目是几路同时出的，互相看不见，以前会出现填空问「ρ 的计算公式」、选择又问「ρ 的表达式」。现在每路拿一片不同的材料，第一路专管核心概念、其余各路明确避开。（这一轮早先的做法是先调一次模型定考点再切给各路，撞考点一样少，但多等 1.5 秒，为了整卷 5 秒内换掉了，见「五、速度」。）
3. **出题加硬约束**——题目必须自足（不准出现「材料中」「如图」）、不考某篇论文独有的数值、答案不许写在题干里。
4. **出完再过一道闸**——违规的题直接删掉，删完不够数才重出。

**现在什么样**：同样填「排队论」，20 题全部落在课程核心内容上（M/M/1、服务强度、Little 公式、仿真时钟推进、逆变换抽样、置信区间等），指代材料的题 0 道。用模型当评委逐卷统计：撞考点和先定考点时持平（每卷近似考点 8.4 对，先定考点时 8.7 对；这位评委统计得很严，同一个点换个问法、填空和选择各问一次都算一对），论文细节题 0 道。

另外三道大题以前全是「给定 λ 和 μ 求指标」只换数字，等于只考了一道；现在固定是计算、建模设计、对比分析各一道，三道分三路出，每路只许出自己那一类，结构上就不会撞类型。

> 实测：整卷中位 4.2 秒，闪卡第一张 1 秒内到，详见「五、速度」。

## 二、答疑

**能接着上文问了。** 以前每次提问只把当前这一句发给模型，问「那它的前提呢」模型不知道「它」指什么。更糟的是**找参考材料时也只拿这一句去找**，实测找到的是供应链和疫情相关的论文——「前提」撞上了论文里的「Pareto 前沿」。回答看着像对的，但依据全错，一旦问到教材里才有的内容就会露馅。

现在会带上前几轮对话，并且找材料时自动把上文的话题词补进去。同一句追问，现在找到的是课程教材。

**设置里的参数真的生效了。** 温度、Top P、最大长度以前调了没有任何反应——前端发出去了，后端压根没读。现在接通了。面板上其余不起作用的开关已经收起来，不再给调了没用的滑块。

**回答被截断会说一声。** 回答到了长度上限（「控制」里的 max_tokens，或模型自己的上限）时，以前停在半截、常常还留着半个公式符号，看不出是被截了。现在末尾补一句「回答到了长度上限……可以调大 max_tokens 再重新生成」，截在公式中间时先把公式收尾。

**追问建议和标签。** 长问题引用时会在合适位置截断并加省略号（以前硬切成半截词）；`M/M/1` 这类记号不会再被当成标点拆散丢掉；追问「那它的前提呢」之后，建议不再写成「请更详细地解释「那它的前提呢」」，标签也不再出「#那它」「#什么」这种词。

## 三、判卷、出卷和接口的几个老问题

- **判卷约一半失败。** 模型判大题时常在每条结果里多写几个字段（比如把「2/3≈0.7」这种算式另起一栏），而判分结果的格式检查是「多一个字段都不行」，两次都不合格就整卷报错。同一张卷实测 10 次里约 5 次失败。现在多写的字段直接丢掉，题号、分数照样严格查；修后 12 次全部判完。
- **不存在的地址回「服务出错」。** 访问不存在的路径、用错请求方法，以前一律回 500「服务内部错误」，还记一条错误日志。现在照实回 404 / 405。
- **知识来源挂了整张卷判不出来。** 判大题时会顺手查几段课程材料当参考；只配了一个知识来源时它一挂，整次判卷就失败。现在查不到就不带材料判（评分要点和参考答案才是依据）。
- **选了个空笔记本还照样出卷。** 闪卡会当场提示「所选知识范围里没有可出题的材料」，整卷却照样去调模型，白等一轮多半报错。现在和闪卡一样当场提示。
- **有人出卷或交卷时，别的同学正在出的答疑回答会卡死。** 后端给每种用途按各自的超时缓存一个模型客户端（答疑 180 秒、出卷 150、判卷 55、闪卡 90……），可新建一个时会把同一个模型的其他客户端全关掉。答疑是边收边往前端送的，连接一被关就停住不动、也不报错（本地假上游复现：收到 4/10 个字后一直等）。这段代码是交接包里就有的，后来用途越拆越多，踢得越来越频繁。现在不同超时的客户端并存，只有登记信息改过才换掉旧的。修后用真实模型实测：答疑出到一半时同时出一组闪卡、一张整卷，回答照样出完，段与段之间最长只隔 0.44 秒。
- **开了 `--lan`，局域网里谁都能拿你登记的 Key 随便调模型。** 给 OpenNotebook 用的透传通道 `/v1/raw` 什么都不加、原样转发，模型、提示词、长度全由调用方定；`--lan` 时前端端口对整个局域网开着，前端代理又把请求全转给后端。现在前端代理给转发的请求盖一个客户端去不掉的标记，`/v1/raw` 见到它就拒绝（403）；OpenNotebook 是直连后端的，不受影响。模型登记页的「试一下」原来也走这条通道，改走要管理口令、只发一句固定短话的新接口。
- **上游卡住时要干等 2.5 分钟。** 出题、判卷这类调用以前一次拿完整段回答，读超时只能设成单次总上限（出卷 150 秒），而且超时不重试。现在一律边收边读：20 秒一个字节都没收到就算卡住，预算内重试一次；一直在写的慢模型（先思考的那类）不受影响，单次总上限照旧宽松。出卷总预算 480 秒是按「三段一段接一段」算的，七路并行后改为 330 秒，前端等待 540 → 380 秒，并加了测试盯着「前端等待 ≥ 后端预算 + 排队 + 余量」。同一时段交替实测，边收边读并不比一次拿完慢（判卷 1.38 / 1.50 秒，整卷 4.00 / 4.31 秒）。
- **端口默认值和实际不一致。** 代码和 `.env.runtime.example` 默认 5000，前端代理、一键脚本都是 5001；照 example 手配、不走一键脚本的人前端一律 502。默认值改成 5001。

- 平台名称统一；中文界面里的 `Exam completed` / `Deck cleared` 改成中文；「WebUI 设置」改名；回答头部显示登记的模型名而不是小写 id。

- **手机上能用了。** 以前 375 像素宽时侧栏默认展开，把对话挤成一条细缝，收起后顶栏的按钮又挤出屏幕点不到。现在窄屏上侧栏盖在内容上、默认收起，点旁边或选完对话就收起；顶栏按自身宽度排，放不下就折成两行，所有按钮都点得到（「临时对话」「数据」在窄屏上收进了设置）。
- 打开右侧「控制」面板时，「课程答疑 / 论文助手」切换按钮不再消失（以前要先关面板才能切）。
- 出题、批改这类一次性出来的长卡片，出来时卡片开头对齐在可视区顶上，不再被滚到论文任务栏后面、看着像被挡住。
- 欢迎页的装饰节点挪到外圈，不再压住大标题和比赛名称。

## 五、速度

### 整卷 5 秒内、闪卡第一张 1 秒内

| | 这一轮之前 | 现在 |
|---|---|---|
| 整卷出题（中位） | 7.2 s | **4.2 s**（10 次全部 ≤ 4.8 s；另一时段一批中位 4.5 s、最慢 5.2 s） |
| 闪卡：第一张出现 | 等整组写完，3.5 s | **1.0 s**（31 次，最慢 1.3 s） |
| 闪卡：整组写完（中位） | 3.5 s | 2.8 s |

（DeepSeek。整卷是同一时段新旧交替跑；闪卡「之前」那列是前一天测的 6 次，只作参考——要紧的是第一张不用再等整组。页面里实测：整卷 3.2～4.2 秒，闪卡点下「开始」到第一张出现 1.1～1.4 秒。）

做了三件事：

1. **连模型服务先直连，直连不通才走代理**（`app/infra/upstream_http.py`）。开发机为了上 GitHub 全局配着代理，以前连国内的模型服务也绕代理出去再绕回来：一段短提示词首字 2.5 秒，直连 0.7 秒。更要紧的是走代理时同时发几路会互相拖慢——这是上一轮「把大题拆三路反而更慢」的真正原因。直连后同时发 8 路，每路仍是 1.9 秒左右。握手失败（请求还没发出去）才换代理重发，并记住这台主机；读到一半断了不重发，免得模型白算一遍。
2. **整卷七路同时写**（`app/agent/graphs/exam.py`）。耗时几乎全花在模型「写」上，写多少字等多久，所以不是让一路写得更快，而是每路少写、多发几路：大题三路各一道，填空、选择各两路，七路同时起步、谁也不等谁。原来挡在填空、选择前面的「先定考点」那一轮（1.5 秒）去掉了，换成每路一片不同的材料、第一路专管核心概念，撞考点持平（见「一」）。
3. **闪卡边写边给**（`app/agent/graphs/flash.py`、接口 `/quiz/flash/stream`）。一片四张卡要写两三秒，第一张写完时才过去不到一秒。现在模型每写完一张，后端当场拆出来、校验、去重、发给浏览器，不等整组。

**试过、没采用**：填空、选择拆成六七路每路两三道（单路仍要两秒多——首字等待、读入几千字材料是每路都有的固定开销——路数多了尾巴更长，反而慢）；把材料放在提示词最前面好让上游复用缓存（缓存确实命中了，首字快了 0.2 秒，整卷没有变快）。

> 出题的秒数受上游当时的快慢影响很大：同一份代码隔一小时复测能差 20%，31 次闪卡里也有 1 次某一片在上游卡了近 30 秒（学生手上已经有卡在刷，只是最后几张晚到）。比较快慢一定要新旧版在同一时段交替跑，别拿不同时段的数字直接比。

### 第一轮：和 v1.0.0 背靠背

同一台机器、新旧版背靠背实测（不调模型的接口各 30 次，出题各 8 次，取中位；出题两行是上面那三件事之前的数字）：

| | v1.0.0 | 当时 | |
|---|---|---|---|
| `/health`、`/v1/models` | 0.4~0.5 ms | 0.2~0.3 ms | 不变 |
| 知识来源自检（笔记本在线） | 30.5 ms | **0.3 ms** | 快 100 倍 |
| 知识来源自检（笔记本挂起） | **5.01 s** | **0.5 ms** | 快 1 万倍 |
| 答疑：收到请求 → 开始调模型 | — | 16 ms（走图只多 0.25 ms） | |
| 闪卡出题 | 3.68 s（8 次失败 1） | 3.83 s（0 失败） | 持平 |
| 整卷出题 | **6.77 s** | **8.23 s** | 慢 1.5 秒（之后已降到 4.2 秒，见上） |
| 判卷（3 批送模型） | 一批接一批 4.32 s | **并发 1.68 s** | 快 2.6 倍 |

**不调模型的接口都在 1 毫秒以内**。自检接口原来每次都现场去问笔记本服务，服务挂起时每次要卡 5 秒；现在改成后台定时去问，接口直接返回上次的结果。

当时整卷慢了 1.5 秒，是出题质量修复的代价：取材换成教材之后大题多成了计算题，模型会把参考答案逐步展开推导，输出长了近一半——已改成参考答案只写要点和关键算式（判分靠的是逐条勾评分要点），大题段 11.5 → 7.9 秒；剩下的 1.5 秒是「先定考点」那一轮，这一轮去掉了。

另外：
- 判卷的几批原来一批接一批，现在同时发，见上表；
- 答疑页每次打开不再把笔记本列表整轮重发，十几秒内复用；
- 每次提问不再额外多打一次笔记本检索，只在后端没给出处时才打。

## 七、具体做法

给要接手或要改这块的人看。

### 答疑：两步拆成三步

原来是 `检索 → 生成`。问题出在「检索」用的是原封不动的那一句——追问「那它的前提呢」里没有一个可检索的实词，于是撞上了无关论文。

现在是 `理解问题 → 检索 → 生成`，每步一个节点（`app/agent/graphs/answer.py`）。

「理解问题」这一步**不调模型**，否则每次追问都要多等一轮，而这一层的目标是「除了模型本身，用户感觉不到延迟」。判断逻辑在 `app/rag/followup.py`：

- 句子里有指代词（它 / 这个 / 该 / 上述 / 前者…），或整句就是一句光杆追问（为什么 / 具体点 / 举个例子 / 继续…），就认定它离开上文检索不出东西；
- 认定了就**往回找上一个自己能独立检索的用户提问**，把它拼到检索词前面。连着追问好几句时会一直回溯，不会拼上另一句指代。

有两个坑写在代码注释里了：一是别把「怎么 / 如何 / 为什么」当指代词（「Little 公式怎么推导」是完全自足的）；二是别用「字数少就算追问」来判（中文实词密度高，「什么是排队论」去掉虚词只剩 5 个字，误判之后会拿上一个话题的材料来答，比不补还糟）。

流式和非流式走同一张图：两条路必须按同一个检索词取材，否则同一个问题换个开关、给出的依据就变了。区别只在最后一步——流式检索完就出图，由外面拿着模型的输出逐块往前端送，原因见下面「怎么拆的」第 4 条。

### 出题：七路同时写，出完再筛

原来是三段（填空 / 选择 / 大题）并发直接出题，每段一次写完整段：大题段要写 2500 字左右，写多少字就等多久；三段互相看不见，于是填空问「ρ 的计算公式」、选择又问「ρ 的表达式」。

现在的顺序（`app/agent/graphs/exam.py`）：

```
取材 ─┬─ 大题 ×3（计算 / 建模设计 / 分析或对比，每路一道，带全部材料）──┐
      └─ 填空 ×2、选择 ×2（各拿一片不同的教材；第一路专管核心概念）────┴─→ 过滤 → 去重 → 组卷
```

1. **大题三路、每路一类**：三类能力类型互不相交（`app/schema/exam.py` 的 `ESSAY_GROUPS`），不是计算类的那两路明说「不能是给定参数求指标的计算题」——只在规则末尾写类型时，「建模」那一路 6 次全出成了计算题。三路少了一路，剩下两道仍够一张卷，不让整卷失败。
2. **填空、选择分材料、分工**：每路一片不同的材料；核心概念每片材料里都有，不点名就每一路都挑它们出，所以第一路专管核心概念、其余各路明确避开。只分教材片段：材料切得小，分到论文片段的那一路只能从论文里挑，出来的全是论文独有的细节。
3. **过滤**：删掉指代材料的、答案写在题干里的（`app/schema/exam_quality.py`）。
4. **去重**：填空和选择放在一起按答案和题干去重（同一个点出成填空还是选择都算撞），去重后跌破题数下限就把删掉的近似题补回几道——一道近似题好过整卷报错。
5. **组卷**：裁到规定题数。

另外，大题的**参考答案只写要点和关键算式**、控制在 300 字内。取材换成教材后大题多是计算题，不加这条时模型会逐步展开推导，输出长了近一半——而判分靠的是逐条勾评分要点，参考答案只是对照依据，用不着完整解题过程。

关键的一条是**留余量**：每路要的题数比「下限 / 路数」多一两道，过滤、去重删掉之后再裁。没有余量时删掉两三道就跌破下限、整路重出、最后报错。

**这一轮早先试过「先定考点」**：先调一次模型列出要考的点，轮流发给填空和选择。撞考点确实少了，但它挡在填空、选择前面 1.5 秒；整卷要压到 5 秒内时放不下，换成了上面的分材料、分工，撞考点持平。各种做法的对比数字在 `app/config.py`「填空、选择不再先定考点」那一段。

### 闪卡：边写边给

一片四张卡要写两三秒，第一张写完时才过去不到一秒（`app/agent/graphs/flash.py`）：

- 每片用流式调用，模型一边写，后端一边用 `app/util/json_items.py` 拆：数组里的一张卡一收口（右花括号）就把它拿出来校验，不等整段 JSON 写完；
- 合格的经 LangGraph 的 custom 流交出去，服务层（`ExamService.stream_flash_deck`）再过一遍泄题检查、跨片去重、编号，一行一个 JSON 发给浏览器（`/quiz/flash/stream`）；
- 一片里坏了一张（比如没挖空）只丢那一张，不让整片重来——重来那一轮会在同一片材料上再出一批，和已经发出去的撞考点；
- 第一行之前的错误（闸门满、选了空笔记本）照旧是普通的 429 / 422；之后某一片失败，已经发出卡就照常收尾，一张没发出才报错，报的是上游那句原话（Key 不对、限流……），不是笼统的「质量不达标」；
- 一次拿完的接口 `/quiz/flash/generate` 还在，走同一套分片，最后照旧组卷、交错排好再返回。

取材那一步（`app/rag/knowledge_base.py`）另有两个要点：候选池要**比最终用的多**，否则按来源配比就没有可挑的余地；挑出来之后要**交错排列**，因为下游还会按条数和字数再截一刀，不交错的话配比挑进来的教材会被整段截掉。

### 判分：能本机算的不调模型

闪卡的对错、整卷的填空与选择都在本机判。只有大题和语义要判的填空才送模型，按题型切成小批**同时发**（`app/agent/graphs/grade.py`）；**逐句批注是点开才算**——不点就不花这一轮，所以不会拖慢交卷。

### 答疑和出题/批改合成一套（为文件编辑铺路）

下一轮要加「文件编辑」——编辑用户上传的文件，形态是**模型给修改建议、用户逐条采纳**。原来每条链路在 service 里各写一套：「算超时 → 取模型 → 调用 → 校验」这一串抄了 7 份，并发出题抄了 3 份，照老样子文件编辑只能抄第四份。所以先把它们收成一套。

**怎么拆的**（`app/agent/`）：

```
app/agent/
  runtime.py   一次运行要用的东西：模型、知识库、截止时间、可调参数；超时怎么算
  nodes.py     共用的一步：带预算、带校验地调一次模型；检索拼材料
  graphs/      每种能力一张图
    answer.py    答疑：理解问题 → 检索 → 生成
    exam.py      整卷：取材 → 七路同时写（大题 ×3、填空 ×2、选择 ×2）→ 组卷
    flash.py     闪卡：取材切片 → 几片同时出、写完一张给一张 →（一次拿完时）删坏卡、去重、交错
    grade.py     判卷：给大题配材料 → 几批同时判
    essay.py     小论文：取材 → 三个维度同时打分 → 被点名的段落才逐句批注
    annotate.py  逐句批注
    edit.py      文件编辑（这轮只铺路）
```

service 那一层只剩门面：检查输入 → 拿闸门 → 准备依赖 → 跑图 → 整理结果。对外接口一个没改，前端不用动。

拆的时候守的几条规矩，都是实测出来的：

1. **模型、知识库这些对象不放进流程的数据里**，随一次运行单独传给每一步。它们不能也不该被逐步复制。
2. **整次运行共用一个截止时间**，几路同时跑时谁都可以用满剩下的时间；以前判卷要把预算按批数切开，改成同时发之后就不用了。
3. **要等别人的放进一张小图里。** 图是一轮一轮推进的，同一轮的全部做完才进下一轮。要是某一步得等另一步（比如早先的「定考点 → 填空 ∥ 选择」），就把这一串打包成一张子图，和不用等的（大题）并排跑，互不等待。现在整卷七路都在同一轮，用不着了。
4. **逐字往外吐的那一步不放进图里。** 实测图在中途被关掉时会等那一步自己跑完：学生点了「停止」，模型照样生成到底、照样计费。所以答疑的流式只让图做前两步，生成由外面拿着模型的输出流来送，一关就断。闪卡是例外：几片要同时写、写完一张给一张，只能在图里经 custom 流往外交；每片两三秒就写完，学生中途离开最多白写这两三秒。
5. **闸门留在门面里**，按「一次出卷 / 一次批改」拿一个名额，图里不再拿。
6. 几路同时跑时**一路出错，会等其余几路结束再报错**（和原来一样），不会出现名额已经还了、模型还在后台跑的情况。

每条规矩都有测试钉着（谁把并发改回串行、把子图拆回平铺、把逐字输出挪进图里，测试会红），测试里也验证过这些写法反过来确实会挂。

**加一条新能力**照这个顺序：在 `nodes.py` 里找能复用的一步 → 在 `graphs/` 里新建一张图 → service 里加一个门面方法（拿闸门、建依赖、跑图）→ 路由。

**文件编辑这轮做到的**（`app/agent/graphs/edit.py`、`app/schema/edit.py`）：给一段文字 → 返回修改建议 → 把用户采纳的几条改回原文。

- 一条修改建议 = 一条批注（落在哪一句、为什么改）+ 改成什么（整句）。直接沿用逐句批注那套：先切句编号、存好每句在原文里的位置，**模型只回编号**，从不回原文片段或位置，查表就能落回原文；
- 改回原文**从后往前**替换，前面的位置才不会被后面的改动挪动；原文在给建议之后又被改过、或两条建议改的范围重叠，就直接拒绝，不去猜；
- 要建议却失败时报错，不回空列表——用户是专门来要建议的，空列表等于告诉他「没什么好改的」。

还没接路由、上传、存储和界面。文件存哪还没定：后端目前**完全没有文件存储**；输入框的「上传文件」是个空壳，只记了文件名、内容没读。存进笔记本服务还是后端自建，要先确认笔记本服务能不能改写已上传的内容，这是下一轮的第一件事。

## 九、已知问题

下面这几条都不是代码缺陷，是设计取舍、模型本身或本机环境的问题：

- **登记模型需要管理口令**，口令在 `TAgent重写版/.env.runtime` 里，对非技术同学门槛偏高。这是有意的：登记模型要填 Key，不能谁都能改。
- 同一张卷子里仍会有近似的考点（几路同时出、彼此看不见），组卷时按答案和题干去重只能去掉一模一样的；换个问法的近似题留着。分材料、分工之后和「先定考点」时持平。
- 题干里出现四个字符以内的英文缩写（如 FIFO）而答案正是它时，过滤器不会判为泄漏。这是有意放宽的——收紧会误删大量合格题，反而导致整次出卷失败。
- **出卷的上游偶尔卡一下。** 31 次闪卡里有 1 次某一片在上游卡了近 30 秒。现在 20 秒一个字节都没有就放弃、重试一次，最坏多等 20 秒左右；上游是慢而不是卡（一直在发），仍然要等它写完。
- 会把思考整段藏起来、一个字节都不发的上游（比如 OpenAI 的 o 系列）可能被误判成卡住，要用时把 `UPSTREAM_STALL_SECONDS` 调大。DeepSeek、Qwen3、GLM 这类会把思考内容一路发过来，不受影响。
- 旧接口 `/quiz/generate`、`/quiz/review`、`/rag/query` 和 `/internal/*` 本仓库里已经没有调用方，但后端 README 还把它们列为主要接口，gitee 上只有后端的仓库可能有别人在用，所以这轮没删。旧出题服务（`/quiz/generate`）也不受出卷名额限制。
- 闪卡出到一半离开（取消、换模式、关页），服务端会把正在写的那几片写完才放手（每片两三秒），这几秒的生成照样计费。这是「写完一张给一张」的代价，见「七」里「拆的时候守的几条规矩」第 4 条。
- 配着系统代理时，连模型服务先直连；直连握手失败才改走代理，并在本次运行里记住、之后一直走代理。换回能直连的网络后要重启后端才会重新试直连。设 `UPSTREAM_DIRECT_FIRST=0` 可回到「有代理就一律走代理」。
- 同一份作答重判，大题得分会有几分出入（实测同一张卷 12 次在 25~32 分之间），是模型自身的波动。
