# OpenNotebook 账号隔离设计（2026-11-09）

## 已确定的产品规则

- 学生用邮箱和密码自行创建 TAgent 账号；目前不验证邮箱归属，邮箱只作为唯一登录标识。忘记密码由管理员线下核验后人工重置。
- 同一账号换设备后，应看见同一份 TAgent 聊天记录，以及完整的 OpenNotebook 笔记、来源资料、上传文件、聊天、播客、模型密钥和个人设置。
- 必须保留 OpenNotebook 原有的完整界面和功能。每个学生只能看见、修改自己的工作空间；模型密钥和设置也由学生本人管理。
- 现有共享 OpenNotebook 内容只归管理员；新学生从空工作空间开始。不自动猜测旧笔记归属。

## 本地实现与待验收项

当前 TAgent 分支已实现账号、课程和 TAgent 个人内容的服务端存储。仅在 TAgent 页面过滤笔记本 ID 不能保护 OpenNotebook 自身的 API、搜索、下载和后台任务，因此完整版 OpenNotebook 单独维护了账号隔离分支 `feat/tagent-account-isolation-20261109`。该分支使用 TAgent 服务端会话、SurrealDB 记录权限和按账号分隔的文件及后台任务；本机两个学生、同账号第二设备和真实数据库的联调已通过。服务器当前仍是 HTTP，分支未部署，不能据此宣称线上隔离或跨设备验收已通过。

2026-11-16 的 TAgent 主线还加入了进程内的精简笔记本，但它使用共享存储，且不包含完整版的播客、模型与凭据管理等功能。最终产品选择是上文所述的**完整版**。账号模式下不得挂载精简笔记本；旧匿名模式可继续使用它。完整版隔离分支在 `D:\Development\SRP\OpenNotebook-auth-20261109`，账号模式的 API 启动检查已在本机真实 SurrealDB 上通过；启动仍要求 HTTPS 来源、身份验证地址、管理员 UUID 和加密密钥。

部署时须同时切换两套分支。TAgent 账号模式下的学生不能回退到共享精简笔记本；完整 Next.js 界面与 OpenNotebook API 要经同一主机的受控 HTTPS 入口，原始后端、worker 和数据库端口不得公网直达。只有完成数据库与上传文件备份、迁移 27、后台旧任务处理、HTTPS 入口及双账号功能验收后，才能开放学生使用。

## 实现方向

1. 以固定的 OpenNotebook 上游提交为基础维护本地分支，保留其完整前端和功能。部署时使用可追溯的自建镜像，不继续用会移动的 `v1-latest` 作为验收依据。
2. 用户从 TAgent 登录后，经同一 HTTPS 主机上的笔记本入口进入完整版界面。OpenNotebook API 从会话 Cookie 向回环地址的 TAgent 服务端查询当前账号，再生成短期数据库记录身份；浏览器自报的账号 ID 和角色不授予权限。完整界面的登录路由只转发必要的注册、登录、退出和会话请求。原始 API、Next.js 与数据库端口不得公网直达，浏览器不保存共享 OpenNotebook 口令。
3. 在 OpenNotebook 的数据访问层建立强制账号范围。笔记本、来源、笔记、上传文件、检索索引、聊天、播客、后台任务、模型凭据和个人设置都按账号分隔。不能只在列表页面过滤；按 ID 读取、修改、删除和文件下载都要校验归属。搜索必须在数据库执行限制后再取结果，不能先全库搜索再在页面删掉他人的命中。
4. 后台命令排队时记录账号，执行时在同一账号范围内读取和写入。跨笔记本引用、来源复用、保存搜索结果等功能只能在同一账号内完成。
5. 迁移前备份原 OpenNotebook 数据和上传文件。旧记录明确标记为管理员归属，学生注册不复制旧内容。异常时回滚镜像与数据库快照，不把旧数据重新公开。

## 验收门槛

- 两个学生和一个管理员分别登录；逐项验证列表、直接访问他人记录 ID、搜索、文件下载、上传、编辑、删除、聊天、播客、模型密钥与设置。跨账号直接访问应返回 403/404，且响应、日志和搜索结果不含他人内容。
- 后台任务在用户退出、换设备及并发提交后仍归原账号；任务结果不能出现在其他账号。
- 同一账号在两台设备上能读取笔记正文、资料原文件、模型设置和 TAgent 聊天；不同账号相互隔离。旧内容仅管理员可见。
- 未登录、伪造身份头、绕过网关直连 8502/5055、缺少 HTTPS 或身份服务不可用时均拒绝敏感请求。
- 通过功能和隔离测试后，再在目标服务器单独做 100 人常态、200 人高峰的验收；本机测试不得代替服务器容量结论。
