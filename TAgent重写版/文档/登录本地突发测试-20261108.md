# 账号登录与轻量接口本地突发测试（2026-11-08）

本记录用于检查账号链路和测试脚本能否在一次同步突发中正确记账。它不是目标服务器容量验收，也没有覆盖长时间运行或真实模型请求。

## 方法

- 在开发机本地启动 Vite `preview` 和仅监听 `127.0.0.1:5009` 的 Waitress 假后端；后端使用真实 Flask 登录路由与 Argon2 密码校验，预置测试账号，以 SurrealDB `mem://` 保存测试身份数据。
- 每档先让所有用户同时登录，再让每名用户访问一个轻量 GET 路径（首页、健康接口或模型列表）；每人同一时刻最多一个在途请求。逐请求记录唯一编号、状态和耗时，逐秒采集后端进程、内存与 CPU。测试不调用模型，也不写入生产数据。
- `mem://` 在此夹具中由单个连接串行处理数据库操作，因此排队行为与远端 SurrealDB 不同；结果只能证明本地链路行为。

| 本地档位 | 计划 / 发出 / 完成 | 失败 / 中断 | 实际在途峰值 | P95 | 后端 RSS 峰值 | 可用内存最低 | 运行时间 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 100 人 | 200 / 200 / 200 | 0 / 0 | 100 | 869.1 ms | 456.2 MiB | 40.09% | 6.3 秒 |
| 200 人 | 400 / 400 / 400 | 0 / 0 | 200 | 1723.2 ms | 498.4 MiB | 39.63% | 7.4 秒 |

两档全部返回 HTTP 200；逐请求编号核对无缺口，监测期间后端未退出，未触发本地内存停止线。Waitress 在突发中出现任务排队（日志中队列深度曾达到 129），P95 包含这段等待。两档只持续数秒，**不能判定 100 人常态、200 人高峰的 3 分钟或更长时长通过**。

原始记录位于 `D:\Development\SRP\stability-results\auth-local-20261108`：`100-requests.jsonl`、`100-resources.jsonl`、`200-requests.jsonl`、`200-resources.jsonl` 与 `summary.json`。测试实现为 `tools/auth_load_fixture.py` 和 `tools/auth_local_load.py`。
