# TAgent 登录与多课程：部署和验收

本分支实现学生自行注册账号、管理员独立账号、课程成员管理，按课程归属的学习记录与模型、笔记本选择，以及账号个人内容的跨设备同步。无 SMTP 时学生使用唯一邮箱和密码，邮箱仅作登录标识，不验证归属，注册后可登录；有 SMTP 时可切换为邮箱验证与邮件找回。`TAGENT_AUTH_ENABLED=0` 是默认值；现有匿名部署不会自动切换。

## 上线前置条件

1. 准备可信 HTTPS 入口；不必有域名，可使用 IP 地址证书及反向代理。`TAGENT_PUBLIC_ORIGIN` 必须与浏览器地址的协议、主机和端口一致。生产环境拒绝 HTTP 和非 Secure 会话 Cookie；现有公网 `http://IP:5173` 不能直接开启密码登录。反向代理应覆盖请求中的 `X-Real-IP` 为实际客户端地址，并只把 5173 暴露给本机代理，否则注册限流会把所有用户当作同一来源。
2. 当前没有 SMTP 时设 `TAGENT_MAIL_MODE=disabled`。学生自行填写唯一邮箱和密码注册，注册后即可登录；系统不验证用户是否真正拥有该邮箱，也不发送找回邮件，邮箱被先注册后不能由另一人再注册。忘记密码需管理员在线下核验身份，再在服务器终端运行重置工具；不要通过聊天发送密码。以后配置 SMTP 时可使用邮箱验证和邮件找回模式；此前未验证的邮箱不能被标成“已验证”。
3. 在现有 SurrealDB 实例内建立**独立的 TAgent namespace/database**，创建只可访问该库的运行账号。OpenNotebook 的现有数据库、账号与口令不搬入 TAgent。按现有数据库运维流程备份两个库。
4. 设置独立的服务端数据加密密钥。可用 `uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` 生成，再放入仅部署进程可读的环境配置；不要提交密钥。轮换时将新密钥放在 `TAGENT_DATA_KEYS` 第一位，旧密钥留在后面直至所有数据已重加密并核验。
5. 保持学习记录 SQLite 可写并备份。账号模式下试卷生成会先保存账号与课程归属；归属无法保存时不会把不可批改的试卷交给学生。

参考配置见 [`.env.auth.example`](../.env.auth.example)。启动脚本需加载该配置中的环境变量；不要把真实配置放入 Git。

## 初始化顺序

1. 用数据库管理员凭据、指向 TAgent 专用 namespace/database 运行 `uv run python tools/init_auth_db.py`。此步骤只建 TAgent 账号表及索引；后端运行账号不持有建表凭据。
2. 用数据库运行账号连接配置运行 `uv run python -m tools.bootstrap_admin`。管理员邮箱在终端输入，密码由 `getpass` 读取，不放在命令行或日志中。
3. 配置 HTTPS、独立数据库与加密密钥后将 `TAGENT_AUTH_ENABLED=1`，启动后端与原有 Vite 入口。`TAGENT_REGISTRATION_OPEN=1` 可使学生自行注册；管理员可在“账号”页暂停或开放注册。
4. 用两个学生测试邮箱完成自行注册、登录、退出、跨设备数据读取。已登录用户可在“我的账号”修改密码，修改后所有设备须重新登录；忘记密码时按实际人工核验流程在终端运行 `uv run python -m tools.reset_student_password`。两种改密方式都要确认旧会话失效、个人数据保留。未登录调用 `/agent-api/v1/models` 应返回 401，健康接口仍可公开访问。再测课程加入、切换、出卷批改归属、导出与测试账号注销。
5. **OpenNotebook 笔记正文与资料的账号隔离尚未完成，当前分支不可作为满足该需求的上线版本。** 现有页面在新标签页打开共享 OpenNotebook；TAgent 只限制检索时使用的笔记本 ID，不能阻止用户经 OpenNotebook 自身入口读取他人的内容。上线前须在保留 OpenNotebook 完整界面的前提下实现服务端的笔记、资料及文件权限，并关闭绕过 TAgent 的直接入口。用户已决定旧共享内容仅由管理员保留，新学生账号从空笔记开始；须按此执行迁移和跨设备验收。

账号模式下，`/opennotebook-api` 代理先向 TAgent 后端核对会话；个人笔记权限完成前，学生所有 OpenNotebook 代理请求均被拒绝，通用区的后端检索也不访问共享 OpenNotebook。管理员仍可使用旧共享内容。若前后端运行在不同进程，请同时保留 Vite 到 basic-agent 的本机连接；后端不可用时代理拒绝转发。旧匿名模式保留原有代理行为。即使代理拒绝学生，请求者仍可能直接访问公开的 8502/5055 端口；部署账号模式前必须关闭这两个公网直达入口。

## 数据与回滚边界

- 旧匿名学习记录保持原样，不自动归到新账号。浏览器旧内容先展示类别和数量，只在学生确认归属后导入账号的通用区；已有服务端数据不会被旧数据覆盖。管理员口令、临时对话和临时试卷草稿不导入。
- 账号的个人内容保存在 TAgent 专用 SurrealDB 中，并由服务端加密。浏览器仅在本次会话缓存账号内容；退出时清掉该账号缓存。离线时账号内容不能编辑，未完成同步时不可正常退出或切换课程。上传失败时本次会话保留待同步草稿；刷新后若服务端版本未变则重试，若另一台设备已更新则保留草稿并提示冲突，不覆盖服务器内容。关闭含未同步草稿的页面会弹出提示；浏览器被强制关闭仍可能丢失这份仅在本机会话中的草稿，需及时导出。
- 同一浏览器切换账号必须先退出，退出会先完成待上传的个人内容；不能在旧账号的上传队列尚未清空时直接建立新会话。
- 多标签页共用浏览器 Cookie。各标签页请求会带自身账号 ID；若另一个标签页已经切换账号，后端拒绝旧标签页请求，避免把旧账号内容写入新账号。若旧标签页还有本机草稿，先导出再刷新。
- 自助注销先停用账号并撤销会话，再清理个人内容和 SQLite 学习记录。若中途失败，账号保持“待完成注销”，管理员在“账号”页重试清理。
- 紧急回滚可将 `TAGENT_AUTH_ENABLED=0` 后重启后端与原版本前端。先备份专用账号库和 SQLite；停用功能不会删除账号资料，也不会把新账号记录变回匿名数据。恢复前应核对 schema 与密钥。
- 服务器部署和 100/200 人验收属于单独阶段。开发机测试只证明代码行为，不能证明目标服务器可承载业务并发。
