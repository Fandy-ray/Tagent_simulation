# TAgent 登录与多课程：部署和验收

本分支实现学生邮箱注册、验证与找回密码，管理员独立账号，课程成员管理，按课程归属的学习记录与模型、笔记本选择，以及账号个人内容的跨设备同步。`TAGENT_AUTH_ENABLED=0` 是默认值；现有匿名部署不会自动切换。

## 上线前置条件

1. 准备正式域名和 HTTPS 入口。`TAGENT_PUBLIC_ORIGIN` 必须与浏览器地址的协议、域名和端口一致。生产环境拒绝 HTTP 和非 Secure 会话 Cookie。
2. 配置能实际送达的 SMTP 邮箱与域名邮件记录。正式模式没有假邮件发送器，邮件配置缺失时账号服务不会启动。先用两个不同邮箱验证注册与重置邮件，不记录邮件里的令牌。
3. 在现有 SurrealDB 实例内建立**独立的 TAgent namespace/database**，创建只可访问该库的运行账号。OpenNotebook 的现有数据库、账号与口令不搬入 TAgent。按现有数据库运维流程备份两个库。
4. 设置独立的服务端数据加密密钥。可用 `uv run python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` 生成，再放入仅部署进程可读的环境配置；不要提交密钥。轮换时将新密钥放在 `TAGENT_DATA_KEYS` 第一位，旧密钥留在后面直至所有数据已重加密并核验。
5. 保持学习记录 SQLite 可写并备份。账号模式下试卷生成会先保存账号与课程归属；归属无法保存时不会把不可批改的试卷交给学生。

参考配置见 [`.env.auth.example`](../.env.auth.example)。启动脚本需加载该配置中的环境变量；不要把真实配置放入 Git。

## 初始化顺序

1. 用数据库管理员凭据、指向 TAgent 专用 namespace/database 运行 `uv run python tools/init_auth_db.py`。此步骤只建 TAgent 账号表及索引；后端运行账号不持有建表凭据。
2. 用数据库运行账号连接配置运行 `uv run python tools/bootstrap_admin.py`。管理员邮箱在终端输入，密码由 `getpass` 读取，不放在命令行或日志中。
3. 初次启用建议 `TAGENT_REGISTRATION_OPEN=0`。配置 HTTPS、SMTP 和加密密钥后将 `TAGENT_AUTH_ENABLED=1`，启动后端与原有 Vite 入口。管理员登录后在“账号”页开放注册。
4. 用学生测试邮箱完成注册、验证、登录、退出和重置密码；确认未登录调用 `/agent-api/v1/models` 返回 401，健康接口仍可公开访问。再测课程加入、切换、出卷批改归属、跨设备同步、导出与测试账号注销。
5. OpenNotebook 在新标签页独立登录。TAgent 课程只记录其笔记本 ID 并限制 TAgent 检索范围；这不是 OpenNotebook 多租户或保密隔离。课程外资料如果需要保密，须另行配置 OpenNotebook 权限。

账号模式下，`/opennotebook-api` 代理先向 TAgent 后端核对会话；学生只可用白名单中的读取和搜索接口，新增笔记本、笔记等共享写入仅管理员可用，写入还校验页面令牌与来源。若前后端运行在不同进程，请同时保留 Vite 到 basic-agent 的本机连接；后端不可用时代理拒绝转发。旧匿名模式保留原有代理行为。

## 数据与回滚边界

- 旧匿名学习记录保持原样，不自动归到新账号。浏览器旧内容只在学生看到提示并确认归属后导入；已有服务端数据不会被旧数据覆盖。管理员口令、临时对话和临时试卷草稿不导入。
- 账号的个人内容保存在 TAgent 专用 SurrealDB 中，并由服务端加密。浏览器仅在本次会话缓存账号内容；退出时清掉该账号缓存。离线时账号内容不能编辑，未完成同步时不可正常退出或切换课程。
- 自助注销先停用账号并撤销会话，再清理个人内容和 SQLite 学习记录。若中途失败，账号保持“待完成注销”，管理员在“账号”页重试清理。
- 紧急回滚可将 `TAGENT_AUTH_ENABLED=0` 后重启后端与原版本前端。先备份专用账号库和 SQLite；停用功能不会删除账号资料，也不会把新账号记录变回匿名数据。恢复前应核对 schema 与密钥。
- 服务器部署和 100/200 人验收属于单独阶段。开发机测试只证明代码行为，不能证明目标服务器可承载业务并发。
